# v0.1 — Event Platform

## Fluxo implementado

~~~text
HTTP POST
   |
   v
Spring Boot
   |
   +--> idempotency_record
   |
   +--> outbox_event
            |
            v
      Outbox Publisher
            |
            v
          Kafka
            |
            v
   Idempotent Consumer
      /           \
     v             v
processed_event  order_event_projection
~~~

## Decisões

- Transactional Outbox para reduzir inconsistência entre banco e broker.
- Idempotency-Key na entrada.
- Idempotência no consumer por eventId.
- Retry e Dead Letter Topic no consumo.
- Flyway para versionamento de schema.
- Actuator + Prometheus para observabilidade.
- Docker Compose para execução reproduzível.

## Limitação consciente

O publisher do outbox da v0.1 é adequado a uma instância da aplicação.
A evolução para escala horizontal deverá introduzir claim/locking com PostgreSQL
ou CDC com Debezium. Essa mudança será feita em uma próxima release.
